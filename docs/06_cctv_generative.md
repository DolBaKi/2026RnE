# 6. 7차 — CCTV 생성형 증강 파일럿 (bear와 동일 구조로 재시도)

> 6차는 "생성 모델로 데이터셋을 만들어 잘 되는지 보고 싶다"는 원래 요청과
> 어긋나 있었다 — COCO 실사진을 그대로 쓰고 Albumentations로 열화만 입혔을
> 뿐, 생성모델은 전혀 쓰지 않았다. 이 문서는 bear(1~5차)와 **정확히 같은
> 구조** — 생성모델로 부족한 조건의 이미지를 직접 만들고, 그것만으로 학습해,
> 진짜 저화질 실사진으로 검증 — 로 CCTV 8클래스를 다시 시도한 기록이다.

## 6.0 무엇이 "부족한 조건"인가 — 재구성

bear가 부족했던 건 "곰"이라는 클래스가 아니라 **"작고 저화질인 곰"이라는
조건**이었다(COCO에 큰 곰은 많은데 그런 조건만 37개). CCTV의 8개 클래스
(person/bicycle/car/motorcycle/bus/backpack/handbag/suitcase) 자체는 COCO
최빈 클래스지만, **"실제 감시카메라처럼 높은 각도·넓은 화각으로 찍힌 이
클래스들의 사진"**은 일반 COCO 사진으로 채워지지 않는다 — 이게 이번에 생성
모델로 직접 만들어야 하는 부족한 조건이다.

## 6.1 파이프라인 — bear의 04/05/06을 8클래스로 확장

구현: [scripts/24_generate_cctv_foregrounds.py](../scripts/24_generate_cctv_foregrounds.py),
[25_generate_cctv_backgrounds.py](../scripts/25_generate_cctv_backgrounds.py),
[26_compose_cctv_synth.py](../scripts/26_compose_cctv_synth.py)

구조는 bear와 동일하다 — 전경(각 클래스, 스튜디오 배경)을 SDXL-Turbo로
선명하게 생성 → GrabCut 분리 → CLIP 게이트 → 배경(CCTV 시점 장면)에 합성 →
Albumentations 열화. 다른 점은 **한 이미지에 여러 클래스가 동시에 등장하는
"장면"**을 구성한다는 것 — 사람이 가방을 들거나 자전거 옆에 서 있는 실제
공동발생을 반영한다(§6.3). 가방류(backpack/handbag/suitcase)는 사람이
착용한 상태가 아니라 **독립된 물체**로 생성해 "전경 하나 = 클래스 하나 =
bbox 하나"라는 bear의 정확한 라벨링 방식을 그대로 유지했다.

## 6.2 실제로 겪은 문제 — GrabCut이 8개 클래스 중 5개에서 깨짐

1차 생성 직후 접촉지를 사람 눈으로 확인했더니 person/car/motorcycle/handbag/
suitcase 5개 클래스에서 컷아웃이 심하게 깨져 있었다 — 사람은 밝은 얼룩
덩어리에 파묻히고, 오토바이는 조각조각 흩어지고, 자동차는 문짝만 잘려
나오는 식이었다. bear는 이런 문제가 없었는데 왜 여기서만 발생했는지 각 전경
클래스마다 8장씩 더 넓게 표본을 뽑아 원인을 진단했다.

**원인 ① 흐린 보케 배경.** 배경 프롬프트 후보 중 "softly blurred neutral
bokeh background"를 쓴 경우에서만 실패가 집중됐다 — 밝은 보케 얼룩을
GrabCut이 전경으로 잘못 잡아 원래 물체와 분리된 조각을 이어 붙였다. 이
옵션을 완전한 단색 배경들로 교체하자 person이 8/8, motorcycle이 7/8로
바로 개선됐다.

**원인 ② 생성 자체의 프레이밍 문제.** car는 배경을 고쳐도 여전히 절반 이상
깨졌다 — SDXL이 "a car, side view" 프롬프트에서 차 전체가 아니라 문짝·바퀴
등 부분 클로즈업을 자주 그렸고, GrabCut은 그 클로즈업을 정확하게 분리했을
뿐이었다(분할 자체는 정상, 생성 프레이밍이 문제). handbag/suitcase는 생성된
이미지에 손이 함께 그려져 GrabCut이 손까지 물리적으로 이어 붙였다. 프롬프트를
"entire vehicle fully visible, not cropped"(car), "alone, no hands, no
person"(가방류)로 구체화해서 해결했다 — car 7/8, handbag 7/8, suitcase 6/8로
개선.

추가로 `compose.grabcut_segment()`에 **최대 연결요소만 남기고 볼록껍질 대비
채움비(solidity) 0.30 미만이면 실패 처리**하는 필터를 넣었다 — bear의
3차 문서(§3.4)에서 이미 "다음 시도"로 남겨뒀던 항목이었다.

## 6.3 다중 클래스 장면 합성

구현: [scripts/26_compose_cctv_synth.py](../scripts/26_compose_cctv_synth.py)

실제 CCTV에서 그럴듯한 조합에 가중치를 줬다 — 사람 단독(24%), 사람+가방류
(28%), 사람+자전거(10%), 차량 단독/사람과 함께(20%) 등 11가지 시나리오.
한 장면 안의 여러 물체가 "같은 거리"에 있어야 크기가 자연스러우므로, 장면
전체에 공통으로 곱하는 거리 배율(작게/보통/크게, 55/32/13%)을 먼저 뽑고
각 클래스의 기준 높이에 곱해 상대 크기를 유지했다. 동행 물체는 주 피사체
옆, 같은 지면선 근처에 배치했다. 최종 420쌍(840장), 거리 분포는
small 225 / medium 142 / large 53 (목표한 결핍 구간을 다수로 구성).

## 6.4 결과 — bear보다 훨씬 나쁘다

학습: YOLO26n, 백본 앞 10개 층 동결, AdamW lr0=0.001, 40 epoch, **cctv_synth_v2
(생성 데이터만, 840장)**. 평가는 학습에 전혀 등장하지 않은 세 세트.

| 세트 | 지표 | baseline | finetuned(생성데이터만 학습) | Δ |
|---|---|---|---|---|
| **real_lowq_cctv** (진짜 저화질) | mAP@0.5 | **0.513** | **0.124** | **-0.389** |
| real_lowq_cctv | recall | 0.450 | 0.149 | -0.301 |
| real_lowq_cctv + 복원전처리 | mAP@0.5 | 0.054 | 0.009 | -0.045 |
| **cctv_val_real** (실사진 clean, 학습에 전혀 안 씀) | mAP@0.5 | **0.352** | **0.074** | **-0.278** |

![결과](figures/fig19_cctv_gen_results.png)

**학습에 쓰인 적 없는 진짜 사진(cctv_val_real)에서조차 성능이 무너졌다.**
이건 6차(실사진+열화로 파인튜닝, -0.090)보다 4배 넘게 나쁘고, bear가
겪은 어떤 결과보다도 나쁘다. 코드 버그가 아니다 — 세 평가셋 모두에서 같은
크기로 무너진 것 자체가 **파인튜닝이 실사진 인식 능력을 광범위하게
훼손했다**는 뜻이고, 원인은 뻔하다: 학습 데이터 840장이 **전부** SDXL-Turbo
생성 이미지라, 사전학습이 수백만 장의 진짜 사진으로 다져놓은 "사람/차/가방이
실제로 어떻게 생겼는가"라는 표현을, 합성 이미지 특유의 결(스튜디오 조명
컷아웃 + 생성 배경의 어색한 이음새, 일부 잔여 GrabCut 결함)로 40 epoch
동안 계속 덮어썼다.

## 6.5 왜 bear는 되고 이건 안 됐는가 — 이 프로젝트 전체의 결론

| | bear (1~5차) | CCTV 생성형 (7차) |
|---|---|---|
| 파인튜닝 전 baseline | 그 조건(작은 곰)을 **거의 모름** (37개 인스턴스) | 그 조건(사람/차/가방 일반)을 **매우 잘 앎** (수백만 장 실사진) |
| 생성 데이터가 하는 일 | 없던 지식을 채움 | 이미 있는 강한 지식을 합성 이미지의 결로 **덮어씀** |
| 실사진 검증 결과 | 개선처럼 보였으나 자체열화 시그니처 과적합으로 판명(+0.079 → 실은 착시) | 처음부터, 그리고 훨씬 크게 악화(-0.389) |

**생성형 데이터 증강은 사전학습이 "거의 모르는" 조건에서만 위험이 적다.**
사전학습이 이미 강한 영역(흔한 클래스의 일반적인 실사진 인식)에 소량의
순수 합성 데이터를 얹으면, 그 강함을 갉아먹을 위험이 오히려 더 크다 — 채울
지식이 없으니 남는 건 "합성 이미지의 인위적인 결을 배우는 것"뿐이기
때문이다. 이건 6차 CCTV 파일럿(실사진+열화, -0.090)과 이번 7차(순수
생성데이터, -0.389)를 나란히 놓아야 보이는, 이 프로젝트 전체에서 가장
중요한 결론이다.

## 6.6 한계와 다음 시도

| 항목 | 제안 |
|---|---|
| 순수 합성 데이터의 도메인 갭 | 생성 데이터를 **실사진과 섞어서**(예: 6차의 cctv_synth 실사진 다수 + 생성 데이터 소량 보조) 학습 — 합성만으로 처음부터 학습하지 않기 |
| 합성 품질 | 잔여 GrabCut 결함(§6.2 완화 후에도 10~25% 남음)을 더 줄이면 도메인 갭이 얼마나 줄어드는지 별도 검증 |
| 학습 스케일 | 840장은 8클래스 COCO 재학습에도, 도메인 적응에도 작다 — 스케일을 키워 결과가 완화되는지 확인 |
| 공정 비교 | 같은 스케일(840장)로 "실사진만"·"생성만"·"실사진+생성 혼합" 세 조건을 나란히 비교하는 통제 실험 |
