# 8. 9차 — 실제 CCTV 장면 5개 + 얼굴 편집으로 특정인 탐지 (YOLO 단독)

> **주제**: 얼굴 데이터셋으로 저화질 CCTV 사진에서 특정인 탐지.
> 찾을 사람(타깃 10명)의 얼굴 데이터셋 사진만 가지고, 실제 인파 장면 **5장**의 얼굴 자리에
> 생성 모델로 그 사람을 편집해 넣어 학습 데이터를 만든다. 박스 좌표는 그대로 라벨이 된다.
>
> **결론 (2026-11-05 갱신)**
> - 생성기 3종(inswapper·SDXL·SD1.5)으로 시험했다. YOLO 단독은 학습한 생성기에서만 잘 찾고(52%),
>   처음 보는 생성기(SD1.5)에서는 8~14%다. inswapper + v4(SDXL)를 섞어 학습해도 SD1.5 에서는 그대로였다.
> - **2단계(YOLO 검출 + 실사진으로 학습한 인식 모델)는 새 학습 없이 세 시험 모두에서 YOLO 단독 이상**이다
>   (inswapper 56 / 75%, SDXL 52 / 22%, SD1.5 23 / 8%, 모스크 / WIDER).
>
> **이전 결론 (2026-11-04)**
> - 조교님 방식(추론은 YOLO 하나)이 **같은 생성기(inswapper)로 만든 처음 보는 장면에서는 통한다.**
>   타깃을 맞는 클래스로 찾는 비율이 5~13% → **52%**(30px 이상 얼굴은 64~66%)로 올랐고, 오탐은 1% 수준이다.
> - 하지만 **다른 생성기(SDXL)로 넣은 얼굴에서는 8~13%**로 떨어진다. 모델이 사람보다 inswapper가 그린
>   얼굴을 배우는 몫이 크다. 이 "생성기 지름길"이 남은 핵심 문제다.
> - 생성 데이터로 학습한 인식 모델도 같은 문제를 보였다: 스왑 시험 88~98% → 저화질 실사진 11~49%.

## 8.0 데이터 — 실제 장면 5장

구현: [scripts/60](../scripts/60_cctv_pseudo_labels.py)(의사 라벨), [63](../scripts/63_cctv_fewshot5.py),
[65](../scripts/65_wider_candidates.py), [66](../scripts/66_fewshot5_diverse.py),
[src/rareobj/cctv_faceswap.py](../src/rareobj/cctv_faceswap.py)

| 항목 | 내용 |
|---|---|
| 장면 5장 | 모스크 CCTV cam06 1장 + WIDER FACE 4장 (밤 거리·동아시아, 실내 모임, 밀집 시위 부감·유럽, 행진·남아시아) |
| 타깃 | 남성 10명 (VGGFace2). 매 장면에 10명 모두 들어간다 |
| 얼굴 편집 | inswapper_128 (SCRFD 키포인트 정렬, best-of-4 × 2회 스왑, 볼 색 맞춤, 디테일 맞춤) |
| 모르는 사람 | 같은 inswapper로 함께 넣는다 — "편집된 얼굴 = 타깃" 지름길 차단 |
| val / test | 모스크 다른 카메라 + WIDER_val 군중 범주. 타깃은 학습에 안 쓴 사진으로 넣는다 |

**품질 작업** — 사용자 기준 "붙여 넣은 티가 나면 안 된다"에 맞춰 반복 수정했다.
- 턱 아래 점선 경계·옷깃 변색 제거: 붙이는 마스크를 턱 타원에서 끝냄.
- 성별 게이트: CLIP(몸)·CLIP(얼굴)·genderage 셋 다 남성 확률 ≥ 0.65인 자리만 쓴다.
- 나이 맞춤: genderage 나이로 타깃 ↔ 자리 헝가리안 배정(잡음 포함). 타깃(41~67세)이
  군중(22~45세)보다 나이가 많아 근사에 그친다.
- 손에 가린 얼굴 등 스왑이 잘 안 되는 자리(시험 스왑 cos < 0.45)는 제외.

## 8.1 생성기 간 일반화 시험셋 (SDXL)

구현: [scripts/69](../scripts/69_sdxl_identity_test.py)

inswapper로 만든 시험만으로는 "사람을 배웠는지 / inswapper 그림체를 배웠는지" 가를 수 없다.
그래서 test 장면의 같은 자리에 **다른 생성기**(RealVisXL 인페인팅 + IP-Adapter FaceID-PlusV2)로
타깃·모르는 사람을 다시 넣었다.
- 머리 전체를 다시 그리면 모자가 지워지고 붙인 티가 나서, 눈썹~턱 타원만 다시 그린다.
- strength 0.75~0.85는 신원이 거의 안 옮겨져서 0.99를 쓴다.
- 신원 검증(CASIA cos ≥ 0.40) 통과: 타깃 213회 중 66회. 최종 80장, 타깃 72명.
- **한계**: 표본이 작고 일부 얼굴은 일그러져 있다(웃는 얼굴·안경·옆얼굴).

inswapper의 그림체를 배운 것이다.

## 8.3 조교님 피드백 (2026-11-03)

> 장면의 얼굴 박스 자리에 생성 모델로 얼굴 A를 editing해서 넣으면 박스 좌표가 곧 라벨이 된다.
> 그 데이터로 YOLO를 학습해 **추론 때 YOLO만으로 얼굴 A를 검출**하는 방식이 바람직하다.
> 실사진 기반 방식은 작동은 하겠지만 contribution이 약해 보인다. 안 되면 그 방향으로 진행.

이전 피드백(연구방법 3.1~3.3)의 "원래부터 저화질인 실사진으로 평가"도 함께 지킨다.

## 8.4 YOLO 단독 특정인 탐지 — 11클래스 (타깃 0~9 + 그 밖의 얼굴)

구현: [scripts/68](../scripts/68_yolo_identity.py), [70](../scripts/70_fewshot5e_bank.py),
[71](../scripts/71_yolo_identity_crops.py)

평가: 타깃 얼굴마다 IoU ≥ 0.5로 맞는 예측의 클래스가 맞는가. 임계값은 val의 타깃 아닌 얼굴이
타깃 클래스로 잡히는 비율 1%(find@FAR1%).

| 버전 | 바꾼 것 | 학습 이미지 | inswapper 시험 (모스크 / WIDER) | SDXL 시험 (모스크 / WIDER) |
|---|---|---|---|---|
| det_mc | YOLO26n, 1280 전체 장면, 학습 105장 (사진 5장 × 변형 20 + 원본 5) | 0% | 0 / 0% | 0 / 0% |
| det_mc2 | + 클래스 가중치, cls 손실 ↑, 150 에폭 | 60% | 5.5 / 13% | 0 / 0% |
| **det_mc3** | 학습 1,005장 (사진 5장 × 변형 200 + 원본 5, 스왑 은행) + 640 조각 + YOLO26s | **99%** | **52.5 / 52%** | 13 / 8% |

- det_mc: 타깃 ~100개 vs 그 밖의 얼굴 15,710개(160:1). 모든 얼굴을 "face"로만 냈다.
- det_mc3 크기별 (모스크 / WIDER): 20~30px 47 / 40%, 30px 이상 66 / 64%. 모르는 사람 오탐 0.7 / 1.2%.
- **스왑 은행** (scripts/70): "자리 × 타깃" 스왑을 한 번씩 만들어 패치로 저장하고, 변형은 패치를
  붙여 조합만 바꾼다. 변형 200장 × 5장을 1시간에 만든다(기존 방식 ~6시간). 신원 cos 중앙 0.670으로
  기존(0.666)과 같고, 확대 시트에서 이음새가 보이지 않았다.
- **640 조각**: 추론 때 1280으로 맞춰지는 크기로 장면을 키운 뒤 잘라, 얼굴 화소 크기는 추론과 같게
  유지하면서 메모리를 1/4로 줄였다(8GB GPU에서 YOLO26s 가능).

## 8.5 생성기 섞기와 제3 생성기 시험 (2026-11-05)

구현: [scripts/72](../scripts/72_v4_bank.py)(v4 은행), [69](../scripts/69_sdxl_identity_test.py) `--gen sd15`,
[71](../scripts/71_yolo_identity_crops.py) `--data --arm --epochs`, [73](../scripts/73_two_stage.py)(2단계)

- **v4 은행**: inswapper 은행과 같은 방식으로 RealVisXL + FaceID-SDXL 삽입을 장면 5장에 만들었다. 100분 제한에
  3라운드, 신원 검증을 통과한 타깃 패치 57개·모르는 사람 18개(밀집 시위 장면은 4개뿐).
- **제3 생성기 시험셋**: SD1.5 인페인팅 + IP-Adapter FaceID-PlusV2 (8차 v3 생성기, 12스텝). SDXL 시험셋과 같은
  80장면·같은 자리. 타깃 84명 통과(모스크 22, WIDER 64). v4와 신원 조건 방식(FaceID)은 같은 계열이라
  완전히 독립된 생성기는 아니다.

find@FAR1%, 모스크 / WIDER:

| 방식 | 학습 데이터 | inswapper 시험 | SDXL(v4) 시험 | SD1.5 시험 |
|---|---|---|---|---|
| YOLO 단독 det_mc3 | inswapper 1,005장, 80 에폭 | 52.5 / 52% | 13 / 8% | 13.6 / 7.8% |
| YOLO 단독 det_mix | inswapper 500 + v4 500, 40 에폭 | 41 / 47% | 26 / 20% | 9.1 / 7.8% |
| YOLO 단독 det_v4 | v4 1,000장, 40 에폭 | 0.5 / 2.5% | 9 / 2% | — |
| **2단계** | det_mc3 박스 + real_deg 인식(생성 데이터 안 봄) | **56 / 75%** | **52 / 22%** | **23 / 7.8%** |

- det_mix 의 SDXL 시험 상승(72명 중 7 → 16명, McNemar p = 0.012)은 학습에 v4를 넣은 효과다. 처음 보는 SD1.5
  에서는 det_mc3 와 같다 — **생성기 하나를 더 섞는 것으로는 지름길이 풀리지 않는다.**
- det_v4 는 v4 패치가 57개뿐이라 학습 이미지에서도 74%에 그쳤다. "v4는 안 된다"의 근거로 쓰면 안 된다.
- 2단계의 1등 후보 정답률은 모든 시험셋에서 67~90%인데 오탐 1% 기준 성공률은 SD 시험에서 낮다.
  확산 모델로 넣은 얼굴은 신원이 약하게 옮겨져(CASIA cos 중앙 0.21) 유사도 점수 자체가 낮기 때문이다.
  SD 시험의 낮은 숫자는 모델만이 아니라 시험셋 품질의 영향도 크다. 표본도 22~64명으로 작다.
- 2단계 오탐은 1.0~1.9% (임계값은 val에서 잡음).

## 8.6 지금까지의 결론

1. 장면 5장만으로도, 변형을 충분히 늘리고 모델을 키우면 YOLO 하나가 같은 생성기 조건의
   처음 보는 장면에서 타깃의 절반 이상을 1% 오탐으로 찾는다.
2. 다른 생성기로 넣은 얼굴에서는 8~13%에 그친다. 1~8차에서 반복된 현상 — 생성 데이터로
   학습한 모델이 대상보다 생성기를 배운다 — 이 여기서도 재현된다.
3. 같은 생성기로 만든 시험만으로 평가하면 성능을 크게 과대평가한다. 교차 생성기 시험과
   실사진 시험이 필요하다.
4. 생성기를 하나 더 섞어도 처음 보는 생성기에는 효과가 없었다(8.5).
5. 생성 편집 데이터는 검출기에, 신원은 실사진으로 학습한 인식 모델에 맡기는 2단계 구조가 모든
   시험에서 YOLO 단독 이상이다. 조교님 원안(YOLO 단독)은 시도했고 그 한계를 측정한 결과로 남긴다.
